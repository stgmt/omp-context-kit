# SPEC: тонкий советник скиллов/рулес — ранжирование, отсев, аудит прочтения

## 1. Цель

Куча правил/скиллов — нормально. Нужен умный доступ: на каждый ход агента находить релевантные ранжированием (BM25 минимум + гибрид), отбрасывать мусор, проверять, читал ли исполнитель скиллы за последние N ходов, и если читал — те ли, что отсеяны. Почти ноль токенов. Работает в длинных сессиях и переживает компакшены.

Пользовательски видимое поведение: агент вовремя получает 3–5 строк «для этого хода релевантны X, Y; Z ты уже читал» — и ничего, когда ничего не релевантно.

## 2. Словарь

- **Куча** — все discovered skills/rules сессии (файлы `SKILL.md`, rule-файлы).
- **Вердикт** — короткое сообщение строгой формы (≤5 строк): строка 1 `Релевантно: <имена через запятую или —>`; строка 2 `Прочитано: <имена/—>`; строка 3 `Причина: <≤10 слов>`; строки 4–5 резерв под эскалацию. Какие скиллы релевантны ходу + статус прочтения.
- **Аудит прочтения** — кольцевой журнал: какие скиллы агент реально читал за последние N ходов.
- **Подавление** — не повторять вердикт, если ничего не изменилось.
- **Эскалация** — усиленный сигнал, если рекомендованное игнорируется N ходов.
- **Честный отказ** — вердикта нет, если ничего не прошло порог.

## 3. Архитектура

```text
Хук turn_end / tool_call          Файлы скиллов/рулес
        |                                    |
        v                                    v
Кольцевой журнал ходов            Индекс (память, per-сессия)
 (что делал + что читал)                     |
        |                                    |
        +-------> Запрос (последний ход, обрезанный)
                          |
            +-------------+-------------+
            |             |             |
            v             v             v
     Триггер BM25   Триггер структ.  Триггер L1-судья
     (лексика,      (глобы на файлы, (быстрая модель,
      0 токенов,     affinity тулов,  свой предикат фаера,
      скор [0,1])    скор [0,1],      вердикт [0,1],
                     0 токенов)       независимо)
            |             |             |
            +------+------+------+------+
                           |
                           v
              Объединение: max НОРМИРОВАННЫХ [0,1] —
              молчание одного НЕ гасит других
                           |
                           v
              Порог на правило + top-K cap + пол отказа
                           |
                           v
             Нужность: отличается ли от прошлого вердикта?
             Прочитано ли уже релевантное за N ходов?
             (прочтенное только подавляет, никогда не бустит скоринг)
                          / \
                    да/прочтено НЕТ/новое
                      (тихо)   |
                               v
                  context-event: дописать ≤5 строк к копии
                  сообщений для ЭТОГО вызова LLM (сессия не тронута)
```

Триггер L1 ВКЛЮЧЁН (дефолт — вкл): LLM-судья срабатывает НЕЗАВИСИМО от остальных триггеров — не ждёт разрешения BM25 (иначе пропуск лексики молча убивал бы правило). Собственный предикат фаера: виток содержит тулколлы, или проза ассистента длиннее M символов, или новое сообщение пользователя; плюс бюджет не исчерпан и мимо кэша. Предикат читает только форму витка, не скоры других триггеров. Модель — только очень быстрая: класс DeepSeek Flash 4.1 / Gemini 3.8 Flash (конкретная модель — параметром). Тонина — гарантиями раздела 5.

## 5. Токен-бюджет (математика)

- Горячий путь: 0 токенов (BM25 + правила в процессе, сети и модели нет).
- Выброс вердикта: ≤ ~150 токенов, только при (попадание ∧ новое ∧ непрочтено).
- L1 (вкл, независимо): модель класса DeepSeek Flash 4.1 / Gemini 3.8 Flash; вход ≤ ~800 токенов, выход ≤ 150 токенов строгого JSON; свой бюджет (лимит вызовов/токенов на сессию) + кэш по хешу запроса; срабатывает сам, не по разрешению BM25; при превышении — автовыкл до конца сессии.
- Нормировка скоров: BM25 — делением на max по куче этого витка; структура — доля сработавших сигналов из списка ниже; L1 — вердикт 0/1 с уверенностью. Без нормировки max() бессмыслен (шкалы разные) — это было дырой.
- Сигналы структурного триггера (исчерпывающе): совпадение глобы правила с активными файлами 0/1; affinity имени тула 0/1; свежесть правила (дни с изменения, нормировано, вес малый). Веса — калибровкой, дефолт равные.
- Токенизатор BM25 фиксируется: lowercase + сплит (стемминг — нет, отдельной фикстурой доказать/опровергнуть на русских перефразировках).
- Ключ кэша: хеш(фичи запроса, версия корпуса); версия корпуса = хеш(имена + mtime + описания). Правка скилла инвалидирует кэш.
- Запрос: обрезанный последний ход — user ≤A символов + move ассистента ≤B символов + имена тулов + активные пути. A/B — калибровкой, дефолт в спеке перед кодом.
- Долгая сессия: единицы выбросов; компакшены не сбрасывают логику (пересчёт stateless каждый виток; журнал в памяти процесса, не в контексте).
- Доказательство тонкости (счётчики сессии): вызовы L1, вход/выход токенов, попадания кэша, подавления, превышения. Это артефакт «thinness receipt» — проверка, а не слова.

## 6. Аудит прочтения (точно)

Считать прочитанным скилл X, если за последние N ходов был вызов `read` с путём `skill://X…` или `*/X/SKILL.md` (видно в хуке `tool_call`). Хранить `(turnIndex, skillName)` в кольце. Вердикт содержит статус: «рекомендовано / уже прочитано / проигнорировано K ходов». Порог эскалации — параметром.

## 7. Пороги и отказ

- Объединение триггеров: combined = max НОРМИРОВАННЫХ [0,1] скоров, источник пишется в аудит; порог применяется ПОСЛЕ объединения. Адверсариал-фикстура: перефразированный виток с нулевым лексическим пересечением обязан маршрутизироваться (через L1/структуру) — молчание BM25 не отказ.
Порог скора на правило + top-K cap + пол: ниже пола — тишина (честный отказ, не «ближайший мусор»). Пороги калибруются на размеченных витках из реальных сессий (включая пропуск halt-правила и ложное срабатывание на код-ревью из сессии 2026-09-10). Повтор того же вердикта подряд — подавление.

## 8. Тесты

- TDD-фикстуры `виток → ожидаемый вердикт` (включая исторические пропуски/ложняки); ворота precision/recall в CI.
- BDD: релевантный скилл предлагается; мусор отсеян; прочитанное не повторяется; игнор N ходов → эскалация; пустая куча/нет попаданий → тишина.
- Perf: скоринг ~30–100 скиллов за виток — микросекунды–миллисекунды, assert в тесте.

## 9. Blast radius

- Новый каталог плагина; ноль изменений ядра OMP.
- Рантайм: синхронный скоринг в процессе, без сети и моделей по умолчанию.
- Отказ: исключение хука логируется, сессия продолжается. v1 — только steer: блокировка тулколлов запрещена (флаг и критерии блока — отдельным решением, не в v1).
- Отключение: удалить/переименовать плагин. Пин версии рантайма + матрица совместимости (философия `omp-context-kit`: OMP — хозяин точек подключения).

## 10. Плагин vs PR в OMP (вердикт)

- **Плагин — да, сейчас**: все точки (таблица выше) существуют и стабильны в 17.3.7.
- **PR в OMP — не нужен для v1**. Кандидаты на апстрим позже: семантический вид условий TTSR, минимальный контекст советника (трек #7766), pre-dispatch гейт (трек #11133). Плюс держать в поле зрения #9698 (relevance gating) и #7158 (repeatMode), чтобы не дублировать движок.
- Апстрим-история по треку «кто читал скиллы»: ишуев нет (проверено) — новизна наша.

## 11. Открытые вопросы

1. Точные значения: N ходов аудита, top-K, пол скора, порог эскалации, A/B запроса, M прозы для L1, веса структуры, версия корпуса — калибровкой, дефолты в спеке перед кодом.
2. L1-судья: РЕШЕНО — включён в v1 с гарантиями выше; модель зафиксирована классом DeepSeek Flash 4.1 / Gemini 3.8 Flash, конкретное имя — параметром. Осталось калибровкой: точные кэпы и лимиты.
3. Нужен ли персист журнала между сессиями (дефолт — нет, свежая сессия = свежий аудит).

## 12. Критерии приёмки

1. Вердикт появляется только при попадании выше порога и только новый.
2. Прочитанные скиллы не предлагаются повторно; игнор → эскалация.
3. Хот-путь без токенов модели; вердикт ≤5 строк.
4. P/R-ворота зелёные; перф-тест скоринга зелёный.
5. Удаление плагина возвращает поведение стока без следов.
6. L1 включён дефолтно и не выжигает контекст: вход/выход в кэпах, повторный запрос — из кэша без вызова, превышение лимита — автовыключение с записью в счётчики.
7. Thinness receipt сессии показывает вызовы/токены/кэш/превышения; превышений лимита — ноль в приёмке.
8. Независимость триггеров: пропуск одного триггера не подавляет остальные; фикстура-перефразировка с нулевым пересечением маршрутизируется.

## 13. Порядок внедрения и не-цели

- Сначала: разметить N витков из реальных сессий (включая пропуск halt-правила и ложняк на код-ревью); иначе воротам не на чем зеленеть.
- Затем: спайк скоринга + пороги; затем плагин; затем ворота в CI.
- Не-цель v1: сабагенты (аудит покрывает только главный цикл сессии); блокировка тулколлов; эмбеддинги (только BM25 + структура + L1).
